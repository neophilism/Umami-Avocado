# Canonical API contract and clients

UA-002 defines the public **foundation** contract. It does not implement workspace
persistence, authentication, scientific results, laboratory dispatch, budgets or
physical approval. A successful liveness response is not operational lab readiness.

## Source of truth and generated artifacts

`services/api/umami_api/contracts.py` owns strict response models and the permanent
SIMULATED / PHYSICAL provenance vocabulary. `main.py` owns the corresponding
FastAPI route declarations. Their OpenAPI 3.1 document is exported deterministically
to `contracts/openapi.json` and served at `/api/openapi.json`. Swagger UI and ReDoc
are disabled; no external documentation scripts are loaded.

The generator emits both clients from that document:

| Consumer | Generated artifact |
| --- | --- |
| Web TypeScript | `apps/web/src/generated/api.ts` |
| Python | `services/api/umami_api/generated_client.py` |
| Reproducibility manifest | `contracts/manifest.json` |

The manifest contains SHA-256 hashes of the exact exported document and both
clients. Generated files identify their contract digest. They are reviewed source
artifacts, not an independent security attestation. Edit the models/routes or
reviewed templates, then regenerate; do not hand-edit generated clients.

```sh
pnpm contracts:generate
pnpm contracts:check
```

These commands use the frozen API environment. The Python test suite also checks
all generated bytes against current source without rewriting stale artifacts, so
the existing Python CI job enforces drift detection. Missing/stale output fails
the build. Generator tests exercise unsupported schemas and check-mode behavior.

The generator intentionally supports only reviewed read-only, input-free GET
operations, required closed objects, local references, string/boolean literals and
enums, bounded strings and the current portable environment-label pattern.
Unknown schema keywords, request bodies, authentication requirements, methods,
versions or unrepresented response statuses stop generation. Add support and
negative tests deliberately when a later approved unit introduces them; never
replace unsupported features with `any` or silently omit authorization.

## Version 1.0 operations

| Method/path | Meaning | Success |
| --- | --- | --- |
| GET `/api/health` | Process liveness and public environment label | `HealthResponse` |
| GET `/api/readiness` | Foundation-only status; DB/artifact integration unavailable | `ReadinessResponse` |

Both responses require `schema_version: "1.0"` and
`live_lab_orders_enabled: false`. Readiness additionally requires
`database_connected: false` and `artifact_store_connected: false`. These flags
cannot be activated by environment strings, extra properties, integer zero,
truthy values or an AI-generated label. Models reject coercion and unknown fields
and are frozen after validation. The environment is a bounded public deployment
label, not a place for private identifiers or secrets.

There are no request body/query parameters or write operations in this contract.
Unexpected API query/body headers are rejected without parsing or echoing the
payload. Trailing-slash redirects are disabled. Error responses use the same
versioned envelope and preserve `Allow` for unsupported methods:

| Status | `error.code` |
| --- | --- |
| 400 | `invalid_request` |
| 404 | `not_found` |
| 405 | `method_not_allowed` |
| 500 | `internal_error` |

Errors return fixed public messages, never request values, validation input or
internal exception details. API responses are no-store and nosniff. This is not
authentication, rate limiting or a complete logging/privacy policy; those remain
separate approved work. No route accepts lab orders or changes provenance.

## Client behavior

```ts
import { ApiClient } from "./generated/api";
const api = new ApiClient(); // same-origin by default
const health = await api.getHealth();
const readiness = await api.getReadiness();
```

```py
from umami_api.generated_client import ApiClient
api = ApiClient("http://127.0.0.1:8000")  # explicit loopback development origin
health = api.get_health()
readiness = api.get_readiness()
```

Clients send only generated GET paths. They do not attach credentials, retry,
follow redirects, make provider purchases or infer physical approval. TypeScript
uses fetch with credentials omitted and supports caller cancellation plus an
overall abort timeout (default five seconds, at most sixty). Python uses the
standard library with a configurable socket timeout (default five seconds,
at most sixty), not a claimed end-to-end execution deadline. Its default transport
does not follow redirects. Both allow explicit HTTPS origins and loopback HTTP;
Python requires an explicit origin, while the web client may use same-origin.
Userinfo, paths, query/fragment and malformed origin/timeout configuration are
rejected before a request.

Responses are bounded to 64 KiB, decoded as UTF-8 JSON and validated against
generated schemas, including required fields, exact versions/literals and unknown
field rejection. TypeScript cancels early rejected/oversized streams; Python reads
at most the limit plus one byte. Invalid media types, encoding, error/status pairs,
unrecognized statuses and payloads fail closed. Transport failures are distinct
from typed API errors and protocol failures; exception messages do not include
raw response bodies or transport details. Explicit structured error details remain
available to the caller and should be handled as untrusted display text.

The provenance enum has distinct immutable vocabulary values. A client receiving
the string PHYSICAL has not verified an experiment, approval, shipment, payment,
food safety or regulatory clearance. Future persisted result schemas and trusted
workers must preserve that distinction and independently enforce authority.

## Compatibility and validation

Changing required fields, literal values or response semantics requires an
explicit contract-version review and consumer update. Adding new endpoints must
not change the behavior of existing operations. Unsupported future versions are
not silently accepted. Dependency locks and existing CI gates are retained.

`contracts/client-examples.json` is a synthetic shared corpus. Python tests bind
its success examples to actual FastAPI responses, and both clients reject its
invalid examples. Additional tests cover malformed/oversized responses, status
mismatches, dependency refusal, timeout/cancellation, redirect handling, invalid
configuration and generation drift. No provider account, physical specimen or
real laboratory result is used.

Local validation uses Python 3.12 and Node 22, matching the declared runtime
ranges. Deployment, physical activity, an installed database/object store and full
compose CI are separate observations; no such success is inferred from unit tests.
